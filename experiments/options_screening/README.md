# 期权市场筛选与综述对照试验

`protocol.json` 保存采集前冻结的预算、查询、RRF 参数、判据和采用门槛。初始生产基线为 `81d61a5`。单宽查询只是获取消融；采用比较使用共同多查询候选池中的现有字面工作流，不把 Codex 已能编排的多查询能力算作新机制收益。

所有题录响应、标注、PDF、全文片段和综述草稿位于忽略 Git 的 `data/options-screening-trial-20261020/`。协议、分析代码、脱敏结果和最终边界说明可提交 Git。尚未完成全流程审计时不得根据排序结果提前宣称试验完成或机制有效。

## 数据与分析

- `bridge.py` 使用官方 MCP SDK 和独立数据目录；持久文件队列避免把客户端等待超时当成作业终止。重启前核对实际进程句柄，恢复查询只找回原候选的会话入口，不加入原始候选池或 RRF 投票。
- `evaluate.py` 冻结候选、研究分组及开发／留出划分；RRF 去掉重复查询与同列表重复文献。未知不是违反条件，预筛通过只是进入全文阶段，分数不用于排除。
- `annotate.py` 将调用方 Agent 意见绑定实际返回的观测、材料摘要和可定位引语；不覆盖已有标注。来源页题名核对已发生，因此不是严格双盲；没有独立专家金标准。
- `rank_trial.py` 复用现有规范化、字面词和中文二元组函数，以固定 10/3/1 权重应用于题名摘要。这是现有能力的试验适配，不声称生产工具已有专门的题名摘要排序端点。基线仅按开发集选择，RRF 固定 k=60。
- `screen_trial.py` 将同一 Agent 判断展开为逐项标准记录，校验语料摘要、观测归属和引语，保留背景候选及待复核。展开在实验排序显示后进行，不是独立语义复测，不能用来证明判断准确率提高。

## 共同基础链路的修复

试验期间合入 V2 的工程复验及新窗口重定向时序修复。下载控件与题名可能异步加载，故等待已配置的可见控件再判断访问；详情页诊断只返回 PDF／CAJ 控件结构与目标地址形状，不返回签名参数值、登录表单或浏览器凭据。此类修复共同用于两组，不是新增筛选机制的采用。

实际详情诊断进一步确认 CAJ 和 PDF 按钮可共用 `cajDown` 标识，须按可见准确文字选择 PDF。首个正常取得的 PDF 为 179 页，带加密标志，但本机未提供密码的默认 pypdf 阅读器已经可读；原校验器只看标志而误拒。修正后保留原字节／哈希及默认可读状态，真正需要打开密码的文件继续停止。这些是两组共用的获取与解析适配，不计入排序或筛选效果。

已发生客户端退出及较长非处理间隔，最终报告须把恢复查询、认证、等待与网络／解析成本分开；不能将单次本地排序纳秒数当作阅读或写作节省。

2026-10-21：第三篇原选文献《股票期权隐含流动性研究》实际为 260 页、约 30 MB，触及初始 200 页资源上限。为保留冻结的两组各八篇名单，试验库通过显式 `--max-pdf-pages 500` 提高两组共用的页数上限，50 MB 和 300 秒限制不变，生产默认仍为 200 页。该变更发生在观察到材料后，须在最终报告中单列为预处理条件调整及恢复成本，不描述为完全未经调整的预注册全文试验。冻结的候选、分组、排序参数、留出结果与采用门槛均不改写。

`fulltext_trial.py` 只通过同一官方 MCP 队列按篇恢复入口、取得原文件和解析，已经成功的结果复用；任一失败即停下等待检查。超时仅代表观察窗口结束，不取消或自动重交原任务。实际运行状态与产物清单写入本地试验目录，不把下载或解析完成称为阅读完成。

13 篇原选材料现已取得并解析，未替换名单。《上证50ETF期权、股指期货的价格发现及影响因素研究》的 PDF 第 57 页触发 pypdf 的每内容流 token 上限。共同解析链路保留该上限，仅在显式采用新输出契约时丢弃该页的全部提取结果，报告 `extraction_failed_pages`，其他页继续按原上限解析；其他类型的资源超限仍使任务失败。原文件不重写，快照、读取、进度和材料准备均保留不可读页，不能将其计入已返回范围。旧消费者未显式请求缺页报告时仍失败，避免把部分结果误认作完整成功。

控制器支持 `--offline` 复用既有文件及 `--resume-failed-parses` 显式恢复已诊断的失败解析；这不增加检索候选或发起重复下载。修复后的完整测试为 81 项通过（含 5 项试验分析测试）。解析完成仍不等于全文阅读、语义核查或综述质量验收。
