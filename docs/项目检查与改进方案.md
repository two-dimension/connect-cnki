## 1. 目标与检查边界

本方案汇总本次对话两轮项目检查的全部发现，共 13 项。目标是先修复内容权限与数据处理边界，再改善文献阅读、任务响应和可维护性，最后通过独立样本验证实际科研效果。

检查覆盖题录导入与去重、全文导入和解析、任务幂等与恢复、证据检索与读取、语料快照、评分与项目导出，以及现有测试和验收文档。当前会话未提供可用的 codebase-memory-mcp 图谱工具，因此按项目规则回退到源码检查。

本轮完整测试为 **76 passed，89.92 秒**，`uv run ruff check src tests scripts` 通过。浏览器测试采用 Edge 与人工页面夹具，不代表当前真实知网页面可用。额外复现使用独立临时库及人工 PDF、题录，不读取或修改真实文献库，不执行真实知网检索或上传。

复现脚本在检查过程中临时执行，未作为回归测试提交；实施时需将下述条件固化为自动化用例。既有测试通过不能证明本方案所列边界已覆盖。

### 证据与优先级

- **已复现**：在临时环境观察到具体行为。
- **模拟旧状态复现**：以人工旧产物状态验证缓存行为，未执行跨版本安装升级。
- **源码确认／待测量**：控制流程可从源码确认，实际性能或故障影响尚未经过压力测试。
- **验收缺口**：依据仓库现有文档和检查结果，尚缺独立质量证据。

P1 表示优先修复的权限边界问题；P2 表示应在下一轮可靠性与科研流程改进中完成；P3 表示需要基准测量后逐步优化。优先级为本方案建议，不是已发生事故的严重度认定。

## 3. 已复现问题及处理方案

### IMP-01：全文评分应继承所引用证据的权限

**现象与影响。** 题录允许发送给 OpenAI、PDF 仅允许本地使用时，直接读取全文会被屏蔽，但在本地保存的全文评分理由仍能进入面向该客户端生成的项目导出文件。导出文件若随后交给外部模型，可能带出原本限制为本地使用的全文衍生内容。这不意味着程序已自动上传 PDF，也没有证据表明真实内容已经泄露。

**原因与位置。** `src/cnki_mcp/screening.py` 的 `Screening.run` 及 `src/cnki_mcp/app.py` 的 `export_project` 使用文献版本的 `rights` 包装评分维度，没有继承维度中 `evidence_ids` 对应证据的权限。

**实施方向。** 保存每个评分维度所依赖的证据和权限来源，输出时对全部依赖执行当前权限检查；工具返回与项目导出复用同一规则，可复用现有 `protected_all`。历史评分优先根据其证据 ID 重建依赖，缺失依赖应明确标记，不应直接沿用较宽松题录权限。复查人工覆盖理由等衍生内容的权限来源，但这些相邻路径目前不列为已复现缺陷。

**验收标准。** 覆盖题录宽松／全文严格、多个证据权限不同、接收方切换、来源许可变化、历史记录等条件。受限评分在工具返回、JSON、Markdown 及伴随清单中均被一致屏蔽；允许处理的评分仍可正常输出。正文屏蔽不得被误记为已返回阅读进度。

### IMP-02：解析流程版本应进入任务幂等身份

**现象与影响。** `parse_fulltext` 的任务参数与幂等键包含 pypdf 版本和配置摘要，但不包含 `pdf_worker.PIPELINE_VERSION`。仅修改项目解析逻辑而保持依赖和配置不变时，再次提交会复用旧成功任务，无法通过该路径获得新解析结果。

**复现边界。** 在临时库中完成一次解析，将其产物的流程版本标为人工旧值，再次提交返回相同任务且未调度新任务。这验证了版本不参与缓存判定；尚未做真实安装包跨版本升级测试。

**实施方向。** 在 `src/cnki_mcp/app.py` 的解析参数和幂等键中加入共享的流程版本；统一版本定义，确保解析输出与任务身份一致。同一流程版本继续复用任务；流程升级生成新解析产物，保留原文件、旧证据和旧综述引用。若需要主动重跑，设计显式入口，避免破坏默认幂等语义。

**验收标准。** 同版本重复提交不增加任务；仅流程版本变化即可生成新任务和新产物；旧快照仍指向旧证据。补充真正的旧库升级回归，验证历史记录兼容性及新旧产物的选择提示。

### IMP-03：默认快照选择应避免无提示的字段退化

**现象与影响。** 先导入包含摘要、卷号、页码的记录，再导入同 DOI 的简略记录。原文献版本仍有完整信息，但新语料快照默认选取最后一次观测，用其中的空值覆盖已有字段。原始数据未被删除；退化发生在快照所采用的题录中，会影响后续材料准备和书目输出。

**位置。** `src/cnki_mcp/review_workspace.py` 的 `snapshot`：默认使用 `observations[-1]`，再将 `observation["fields"]` 合并到题录。

**实施方向。** 优先增加字段退化提示和明确的观测选择结果，允许调用方选择完整且合适的观测。若进一步实现跨观测字段补全，必须保存字段来源、相应权限及冲突说明，不能把拼接后的信息伪装成某一次原始观测。调用方显式指定观测时，应尊重其选择并展示缺失情况。

**验收标准。** 稀疏重导入后默认快照不会无提示地丢失摘要、卷号和页码；显式观测仍可准确重放；冲突值和真正删除值不能被静默覆盖；补全摘要不沿用错误观测的权限。历史快照保持不变。

### IMP-04：RIS 起止页码应完整导入

**现象与影响。** 人工 RIS 输入 `SP=101`、`EP=109`，`parse_records` 仅保存 `101`，导致引用页码范围不完整。

**位置与方向。** 修改 `src/cnki_mcp/citations.py` 的 RIS 分支，读取并规范组合起止页。区分已有页码范围、仅起始页、单页及缺失字段，避免重复拼接。

**验收标准。** `101/109` 得到 `101-109`；单页与缺失结束页保持合理；已有完整范围不重复追加。覆盖 RIS → 本地记录 → RIS／CSL／文本书目的往返，并加入合法取得的外部软件导出样例。

### IMP-05：证据上下文应按预算逐步缩减

**现象与影响。** 同一命中在 1,200 字预算、`context_blocks=0` 时返回 1 条证据；`context_blocks=1` 时因整组上下文超限，返回 0 条且标记截断。材料准备默认使用相邻上下文，在分配到较小预算时可能出现本可避免的缺口。

**位置。** `src/cnki_mcp/review_evidence.py` 的 `search` 和 `src/cnki_mcp/review_preparation.py` 的 `run`。

**实施方向。** 候选超预算时，逐步减少相邻块，优先保留命中块。命中块自身仍超限时返回明确的预算不足状态和续读定位；如需裁剪，记录精确偏移与实际返回范围。区分没有关键词命中、权限屏蔽、预算不足和上下文截断，避免将不同原因统一表述为材料缺口。

**验收标准。** 上述 1,200 字条件下可返回命中块，并标记上下文不完整；结果不超预算、不重复计入重叠文本，原证据身份可追溯。增加多篇材料准备测试，检查分配顺序是否导致持续偏向某些文献。

### IMP-06：基础全文读取应提供续读位置

**现象与影响。** 人工长页有 11 个证据块，基础 `read_paper` 首次仅返回 5 个并提示 `truncated=true`；传入 `evidence_offset=5` 则返回 `INVALID_ARGUMENT`，因为当前续读要求项目快照上下文。基础读取路径因此不能直接读完该页。

**位置与方向。** `src/cnki_mcp/app.py` 的 `read_paper`。复用增强阅读的排序、预算与续读逻辑，为基础模式返回下一读取位置，并绑定版本、解析产物和页段。基础续读不应要求启用增强综述，也不应隐式创建综述成果。

**验收标准。** 关闭增强综述时仍可通过连续调用覆盖长页全部证据；重复请求确定、无遗漏，重叠块处理明确。读取预算小于单块时有明确提示，不能无限返回同一位置。续读保持原解析版本并执行现有输出权限。

### IMP-07：预算应按实际新增文献计算

**现象与影响。** 项目预算为 1，首次导入 1 篇成功；再次导入完全相同的题录仍被 `BUDGET_EXCEEDED` 拒绝，虽然文献数不会增加。

**位置。** `src/cnki_mcp/app.py` 的 `import_records` 在去重前用已有数量加输入条数判断预算。

**实施方向。** 复用保守去重规则计算实际新增版本数，或在不含异步等待的受控事务内完成导入并检查最终数量，超限则整体回滚。匹配到已有版本仍可追加观测；标识冲突不能为了通过预算而强行合并。验证批内重复和跨项目已存在版本的计数。

**验收标准。** 预算用满后允许重导入相同文献；新增文献超限仍拒绝。混合批次、批内重复、冲突版本及失败回滚均保持正确的项目数量和观测状态。

## 4. 工程优化与待验证事项

### IMP-08：隔离同步耗时操作

`src/cnki_mcp/citations.py` 在异步工具调用链中使用同步 `subprocess.run`，渲染超时为 30 秒；`src/cnki_mcp/parsing.py` 的文件登记也同步调用 `inspect_pdf`。这些操作执行期间会占用事件循环。尚未测量真实文件下的响应延迟，不据此断言已发生超时。

建议引文渲染改用异步子进程，PDF 结构检查使用可限制时间的独立进程；统一处理取消、超时、子进程回收和临时文件清理。不要将共享 SQLite 连接随意移入工作线程。

验收采用可控的慢渲染器和慢检查器：长操作执行期间，任务状态查询应可完成；取消后没有残留子进程；超时错误可以区分；失败不登记不完整资产。先测量响应分布，再确定实际文件测试的性能门槛。

### IMP-09：任务队列增加并发控制

`src/cnki_mcp/jobs.py` 的 `schedule` 直接为每个任务创建执行任务；不同资产的解析可同时启动多个进程。已有同会话浏览器锁不等于解析任务的全局资源上限。

建议增加按任务类别的并发配置，解析初始值可从 2 个开始验证。未获取执行名额的任务保持 `queued`，明确等待原因；运行后才进入 `running`。处理排队取消、退出恢复、公平调度和失败后的名额释放。

验收以批量人工任务记录并发峰值、内存与完成时间。并发不得超过配置值；排队取消不启动解析；某任务失败不阻塞后续任务；重启后不重复提交已完成工作。并发数属于待测参数，不承诺所有机器适用同一个最优值。

### IMP-10：错误分类与脱敏诊断

`src/cnki_mcp/app.py` 的通用包装将部分 `OSError`、`KeyError`、`TypeError` 等统一转成参数错误；`src/cnki_mcp/jobs.py` 的未知异常统一为 `INTERNAL_ERROR`。文件权限问题或内部缺陷可能因此被提示为输入不合法，现有审计也不足以区分其根因。

建议区分输入校验、文件读写、依赖缺失、来源布局、超时和内部错误；将允许列表中的异常类别、失败阶段、请求／任务标识写入本地诊断。对外提供可执行的恢复建议，内部编程错误不应默认要求用户修改输入。继续不记录账号、会话秘密、完整来源 URL 或正文；不得直接把未清理的异常消息写入日志。

验收分别注入错误输入、文件权限失败、渲染器缺失和内部异常，检查错误码与恢复建议。确认诊断可定位阶段且不包含测试用敏感标记，stdout 仍只用于 MCP 协议。

### IMP-11：自动检查流水线

当前仓库检查未发现 `.github` 下的工作流；这不排除存在仓库外部的 CI。建议以锁定依赖安装、Ruff、非浏览器测试和打包检查为基础流水线；浏览器夹具在具备所需环境的任务中运行，不访问真实知网。

打包验证应检查样式、语言文件、JS helper 与锁文件是否齐全，并确认本地配置、PDF、数据库、认证状态和开发依赖未进入分发包。平台矩阵以声明支持范围和实际维护成本决定，不以扩大矩阵替代有效用例。

验收应能从全新工作目录安装并通过检查；不依赖开发者个人路径、现有配置或手工登录。CI 使用人工数据，失败能回溯到提交与明确检查项。

### IMP-12：为高频读取提供索引查询

多处通过 `Store.all` 将某类全部记录读入内存后筛选，例如全文证据读取、快照构建、观测查找和任务幂等查找；部分调用还位于逐篇循环中。现有按记录类别的索引不能消除这些 Python 层全量加载成本。增强综述已有按项目索引查询，可以沿用其思路。

建议先记录基线，再增加按 `version_id`、`parse_artifact_id`、`asset_id`、任务幂等键等查询的 Store 接口与必要索引，优先替换证据和观测的热点路径。任何 schema 修改继续使用现有迁移备份和回滚机制。

验收使用不同规模的人工文献、观测及证据集合，测量耗时分布、内存和查询次数，核对结果排序及内容完全一致。性能达标值在基线测量后确定；本轮不宣称已发现真实大库性能故障。

### IMP-13：建立独立的真实质量验收集

现有工程测试和八篇材料回归可以验证流程运行，但不能替代题录准确率、去重可靠性、引文格式与综述事实支持的独立验收。具体缺口以 [验收状态](验收状态.md) 和 [项目实施规格](学术文献MCP项目实施规格.md) 为准，不改写原有目标。

建议建立固定且可追溯的样本集，优先覆盖：

| 任务 | 样本重点 | 记录方式 |
| --- | --- | --- |
| 题录 | 摘要缺失、页码范围、不同发表类型、字段冲突 | 字段正确／错误／未知及来源 |
| 去重 | 同 DOI 冲突、同题不同文、学位与期刊版本 | 误合并、漏合并及关系判断 |
| 引文 | 中英文作者、卷期、页码、不同文献类型 | 与目标格式逐项比对 |
| PDF | 文本、扫描、复杂版面、内容流失败 | 可读范围、页码定位、关键内容遗漏 |
| 筛选与综述 | 核心文献、争议纳排、反证、关键数字与方法 | 错误排除、过度推广、事实支持和复核耗时 |

由熟悉课题且尽量独立于生成过程的研究者给出判定，保留分歧、依据和修改原因。同一 Agent 生成后再自评不能替代独立人工金标准。按原规格确定样本规模与门槛；未达门槛应报告实际错误及限制，不为达到数字而调整测试集合。
