## 已有测量

测量环境为本机 Windows 11 / Python 3.12.7，使用临时目录、人工数据和受控子进程。索引比较是在同一当前运行环境中执行原 `Store.all` 加 Python 筛选的参考实现与索引查询，不是历史二进制整体性能对比。

| 总证据数 | 命中数 | 全量参考中位数 ms | 索引中位数 ms | 全量/索引 Python 峰值分配 |
| ---: | ---: | ---: | ---: | ---: |
| 500 | 10 | 2.715 | 0.097 | 1,056,924 / 24,197 B |
| 5,000 | 10 | 56.099 | 0.100 | 10,602,891 / 24,230 B |
| 20,000 | 10 | 574.907 | 0.116 | 42,461,630 / 24,263 B |

每组 12 次，排序和内容完全相同，查询计划实际使用 `records_parse`；每次 SQL 查询数均为 1，加载记录从全类数量降为 10。Python 分配不含 SQLite 原生内存。这里的达标判断为结果一致且同机各规模索引耗时与内存均低于参考实现，不外推为实际大库服务 SLO。原始结果见 [improvement-performance.json](validation/improvement-performance.json)。

并发参数 1/2/4，各运行 12 个“分配 4 MiB 后等待 100 ms”的 Python 子进程，实测工作区间并发峰值分别为 1/2/4，完成耗时约 4.78/2.34/1.40 秒。重叠工作区间内各子进程峰值 RSS 的合计上界约 32.8/65.7/131.3 MiB；该值不是同时采样的系统总 RSS。测量验证限制生效及时间/内存取舍，不据此认定所有机器解析 PDF 的最优并发。

将实际检查/渲染调用替换为受控 30 秒子进程，分别测 40 次 `get_job` 应用工具函数调用：PDF 检查期间 p95 为 2.975 ms，CSL 渲染期间为 2.562 ms。两组取消后均回收子进程、清理暂存文件且不登记资产/导出。该测量不含 stdio 传输或真实 PDF/CSL 负载，不设生产延迟承诺。原始结果见 [improvement-responsiveness.json](validation/improvement-responsiveness.json)。
