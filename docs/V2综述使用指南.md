# V2 可选综述使用指南

版本 0.2.1（V2 功能始于 0.2.0）。总计 39 个工具、3 个资源和 3 个提示。V2.1～V2.3 的工程接口已经交付；同一真实课题的综述质量与人工对照验收尚未完成。

## 启动与选择

重新连接项目中的 `cnki_literature` MCP，使客户端重新获取工具 Schema。服务首次使用旧库时自动生成一致备份，然后升级至 schema 4；升级失败回滚。不要让新旧服务同时占用同一个数据目录。

新旧项目的 `review_assistance_enabled` 默认 false。用户明确选择某项目后，调用：

```json
{"project_id":"<实际项目 ID>","enabled":true}
```

以上是 `set_review_assistance` 的参数。启用仅保存选择，不自动检索、下载、筛选或生成正文。基础显式 `prepare_review`／`save_review` 仍可独立调用，不会隐式启用增强辅助。

## 阅读成果与快照

1. `save_review_plan` 保存目标、子问题、范围、纳排标准、关键词、同义词、章节职责和术语。`planned_queries` 仅保存计划，`executed_query_ids` 关联实际查询；在线执行仍使用已核验的 `search_papers` 能力。
2. `create_corpus_snapshot` 显式选择 items，逐项指定 version_id，并可指定 observation_id、asset_id、parse_artifact_id。不指定解析时沿用已选解析，尚未选择则使用最早解析；要采用新解析必须明确指定。题录、作品关系、资产及解析关系在快照中固定。
3. `read_paper` 携带 project_id、snapshot_id 和页码；返回 `continuation` 时可直接采用其中的参数续读，绑定原解析和页段。基础模式也支持续读，不要求启用增强功能。若 `budget_too_small=true`，参考 `required_chars` 提高配置预算，此时不返回重复位置。相邻重复文本按位置合并，原始 evidence_ids 全部保留。
4. `search_evidence` 可指定 version_ids、section_name、reading_levels、context_blocks 和 plan_id。中文检索使用字面匹配、字符二元组及计划同义词；上下文超预算时先保留命中块。`version_status` 区分未命中、权限屏蔽、预算不足及数量限制，`context_truncated` 说明邻块缺失；uncovered_version_ids 不代表论文没有相关内容。增强材料准备可按份额返回命中摘段，`source_ranges` 标明精确范围，阅读进度只记实际可输出部分。
5. `save_paper_card` 保存字段及 references。原文陈述或作者解释需实际证据；摘要引用使用 observation_id，不能填写虚构 PDF 页码。未取得的信息保留 null。章节页段由 Agent 或用户登记，verified_by_user 仅在用户实际确认时声明。

每篇文献在项目中保留一张稳定文献卡。修订时提交 entity_id 与 parent_revision_id，parent 必须为当前 id。字段名不能重复。返回的 asset/hash/pages 等计算字段不应直接回填输入模型；以 MCP 输入 Schema 为准。

材料层级只表示可用资料。进度分别记录材料状态、通过出站策略实际返回的范围、抽取字段与声明的人工核查。解析成功、返回全部页面、模型判断均不证明完整理解。

## 比较、分节写作与核查

1. `prepare_synthesis` 或显式带 snapshot_id 的 `prepare_review` 提交本地材料准备任务，返回 job_id。通过 `get_job` 取得结果；材料按问题检索、复用冻结的卡片版本，服务不额外调用模型。
2. Codex 使用 `review_section` 提示，按需采用 WRITE-01～12，填写 `save_synthesis` 的主题与 claims。每个来源关系分别为 supports、contradicts、qualifies、background；同作品、相同 PDF 和声明的共同数据不重复计为独立支持。组数不是独立性认证。
3. `save_review` 增强调用需 body、snapshot_id、section。section 指定 plan_id、synthesis_ids、card_ids，以及提纲、依据、反证、章节上下文。正文以 `[version_id]` 引用；paragraphs 的文本用两个换行连接后必须等于 body。
4. 新主题、论断、来源、段落的标识由服务产生。更新这些对象时保留上一次返回的稳定标识；不得借用其他成果的标识。修订整个成果仍须提交 entity_id 和 parent_revision_id。
5. 服务扫描完整正文建立逐句清单，而不只检查已提交的 claims。自动匹配只认句中实际出现的论断文本；改写句应由核查明确补映射。未判断句子继续排队，不把清单覆盖率解释为事实正确率。
6. 使用 `review_check` 提示进行事实、结构、语言分轮审查，通过 `save_review_check` 保存支持意见、句子分类、反向提纲与问题。模型意见与调用方声明的用户判断分别保存；没有身份认证或自动语义认证。数字、单位、否定和不确定性签名仅为变化提示；语言轮修改正文后同样需重核事实与条件。

`get_review_progress` 返回缺卡、未知字段、逐句队列、过期依赖与下一步。`get_review_artifact` 支持按类型分页、通过 entity_id 读取当前版本，或通过 revision id 重放历史。

## 修订、暂停与导出

`get_review_impact` 可传 changed_ids 查看反向依赖；同时传 base_revision_id、target_revision_id 查看同一成果的差异。新增论文只提示覆盖复核，其他解析只作为可选材料，不自动改写旧快照。采用新快照或修订依赖后，相关核查对当前工作标为 outdated；原始正文与旧判断保留。

人工段落默认保留。Agent 修改或删除人工段落会得到 USER_EDIT_CONFLICT；确需针对该段修改时，显式设置 allow_user_edit_changes，并保留父版本和原因。生成其他章节不会覆盖既有章节。

关闭项目会使增强材料作业在完整单元检查点暂停，保留卡片、正文和历史。重新启用后调用 `resume_job` 才继续；不自动重放下载或解析，不取消共享基础任务。服务退出和重启也保留检查点。

`export_project` 默认只含基础记录。显式 include_review=true 加入历史综述、卡片、快照、核查问题和正文；format 为 json 或 markdown。review_revision_ids 选择章节版本及顺序，正文与书目在同一次 CSL 渲染中统一编号；同版本题录快照冲突时拒绝混合导出。Markdown 的 JSON 清单保留完整结构化产物。

关闭后仍可读取与导出历史。增强派生内容同时满足 review 与所用 abstract/fulltext 的出站限制，包括作业缓存、差异和导出清单。综合文稿保守继承选定语料的全部限制；材料许可不一致时可显式缩小快照。身份、引语或工程测试通过，均不代表学术结论通过。

## 复现工程验证

```powershell
$env:CNKI_TEST_BROWSER_CHANNEL = 'msedge'
uv run pytest -q
uv run ruff check src tests scripts
uv run python scripts/validate_review_protocol.py --output docs/validation/review-v2-protocol-validation.json
uv run python scripts/validate_review_v2.py --output docs/validation/review-v2-validation.json
uv build
```

`validate_review_protocol.py` 通过官方 SDK 启动真实 stdio 子进程，使用人工记录和独立临时库检查工具契约及增强调用，结束后清理临时库。`validate_review_v2.py` 只读原库，通过 SQLite backup API 创建忽略 Git 的隔离副本，复用既有八篇写作观察材料。后者验证工程定位片段、卡片、主题关系、声明的用户编辑保留、局部影响、重启和关闭后的双格式导出；不进行新检索或模型调用，也不生成可冒充学科综述的结论。原始 PDF 与全文派生中间产物只保留在本地忽略目录。结果与局限见《验收状态》及 JSON 报告。
